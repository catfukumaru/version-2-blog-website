Introduction to Analytical Software Engineering Design Paradigm - A summary

Date: 10/05/26

Introduction

In this article I'll summarising the paper "Introduction to Analytical Software Engineering Design Paradigm".

Definition and principles of analytical software engineering(ASE)

Definition of ASE

The process of “encoding and representing a software engineering problem in a manner that enables the problem to be processed and analysed using a broad range of mathematical, analytical, and algorithmic tools, without requiring significant adaptation of those tools to t the problem”.

Principles of ASE

  • Abstraction and compatibility: Distilling problems into abstract representations while keeping their accuracy.
  • Decoupling Interpretation from Processing: Result interpretation is deferred to later stages. This approach allows the computational process to concentrate solely on executing the necessary calculations and optimizations.
  • Minimization of Processing Tools Adaptation: The problem is abstracted in a way that reduces the need for change of processing tools for the problem.
  • Scalability: The approach needs to remain both effective and efficient as the problem scales.

Qualities of ASE

  • Primarily addresses specific analytical challenges, like code structure optimization, by generalizing the problem representations to for efficient processing.
  • Covet the whole software lifecycle, with a focus on the methodologies and frameworks that oversee software development and evolution.
  • It's facilitating the integration of advanced analytical techniques to analyse and optimize software artifacts.
  • Is method-agnostic and can be seamlessly integrated with existing development paradigms.
  • Ensuring compatibility with diverse tools to facilitate optimization and analysis.
  • Introducing a language-agnostic framework for problem abstraction.

Empirical evaluation and discussion of the ASE paradigm approaches

Comparison of for design pattern detection results:

Compared to ASE-based BSS (Behavioural-Structural Sequences) with DPD_Att, DPD_F, and FeatureMap.

  • The BSS approach achieved an accuracy of 92.52%, DPD_Att had 86%, DPD_F attains 80.75%, FeatureMap had 52.93%
  • The BSS model has a precision of 92.55% and recall of 92.52%
  • BSS achieved full coverage of all 23 GoF design patterns.

Results for Search-Based Refactoring using ODR- Optimized Design Refactoring

  • Compares the ODR(ASE based) framework against AST-Based Approaches (ATBA) and Graph-Based Approaches (GBA).
  • ODR its ability to eliminate the need for separate solution representation, significantly reducing computational complexity.
  • The ODR framework also introduces lower memory usage.
  • provides comprehensive tracking of object associations, inheritance, and interface implementations, ensuring a more structured and coherent refactoring process.

Negatives

  • Limited explainability.
  • Limited code behaviour preservation.
  • Struggle with data-driven systems that handle petabyte-scale data.
